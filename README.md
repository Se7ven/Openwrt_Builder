# OpenWrt & ImmortalWrt Builder (GL-MT5000 / Brume 3)

*🇩🇪 [Deutsche Version unten / German version below](#-deutsche-version-german-version) | 🇷🇺 [Русская версия / Russian version below](#-русская-версия-russian-version)*

> ⚠️ **Important Note regarding Snapshots & Package Management:** 
> All firmware images generated by this repository are **development snapshots**. Due to the rolling nature of snapshot builds and strict kernel version bindings in OpenWrt/ImmortalWrt, **kernel-dependent software (such as kernel modules or drivers) cannot be installed post-installation** via package managers (like `apk` or `opkg`). Any required kernel-bound modules or features **must be explicitly selected and integrated directly into the build process via the configuration list (`.config`) beforehand**.

This repository contains two distinct build architectures tailored for the **GL.iNet GL-MT5000 (Brume 3)** router: the universal GL.iNet source-based builder and the vanilla OpenWrt/ImmortalWrt source-patch builder.

---

## 🚀 The Dual-Builder Architecture & Script Allocation

### 1. The GL.iNet Source-Based Builder (`build-gl-mt5000-glinet.yml`)
- **Purpose:** Universal source code compilation using the official, native GL.iNet source tree (`mt5000` branch) as its kernel and driver foundation.
- **Workflow & Selection:** Controlled via a `workflow_dispatch` dropdown (`target_env`) supporting 4 environments (`immortalwrt_master` [default], `immortalwrt_stable`, `openwrt_main`, `openwrt_stable`) for targeted single builds, or `all` to trigger a parallel matrix build of all 4 variants simultaneously.
- **Assigned Scripts:**
  * `sh/scripts-part1.sh`: Pre-feed script executed right after cloning the native GL.iNet tree; sets default IPs (e.g., `192.168.100.1`) and configures branch feeds.
  * `sh/scripts-part2.sh`: Post-feed customization script that clones third-party packages (themes, diskman, etc.) into `package/custom`, resolves Makefile conflicts, and handles network layout and branding.
  * `sh/finalize.sh`: Post-build script for organizing, renaming, and packaging final firmware artifacts with timestamps.

### 2. The Vanilla Source & Patch Builder (`Imagebuilder gl-mt5000.yml`)
- **Purpose:** Pulls upstream vanilla OpenWrt or ImmortalWrt source code directly and applies custom kernel patches, device tree sources (DTS), and driver modifications during a full compilation process using dedicated helper scripts and patch directories.
- **Workflow & Selection:** Controlled via a `workflow_dispatch` dropdown (`target_env`) with `immortalwrt_master` set as default. Allows building a single specific environment (`immortalwrt_master`, `immortalwrt_stable`, `openwrt_main`, `openwrt_stable`) or selecting `all` to compile all 4 environments in parallel via a dynamic JSON matrix.
- **Assigned Scripts & Folders:**
  * `sh/clone.sh`: Helper script for cloning specific upstream repositories and setting up isolated target directories.
  * `sh/prepare.sh`: Prepares the source tree, injects custom device tree sources (DTS) from `board/`, and applies necessary kernel patches.
  * `sh/finalize.sh`: Renames, finalizes, and packages the compiled firmware images for release.

---

## 📁 Repository & Folder Structure

- `.github/workflows/`: Contains all automated CI/CD build and release pipelines (including `build-gl-mt5000-glinet.yml` and `Imagebuilder gl-mt5000.yml`).
- `board/`: Contains hardware-specific board definitions, Makefile targets (`filogic.mk`), device configurations, and device tree assets.
- `config/`: Firmware-specific configuration profiles (e.g., `mt5000.config` and `immortalwrt.config`).
- `default-settings`: Custom default settings package for personal configurations (not currently in use).
- `files/`: Rootfs overlay copied directly into the target file system during the build.
- `patches/`: General kernel and source code patches applied during vanilla builds.
- `patches-25.12/`: Version-specific patch sets tailored for the 25.12 stable release branches.
- `patche618/`: Kernel 6.18 specific patches and driver adjustments.
- `sh/`: Houses all modular helper and customization scripts (`clone.sh`, `prepare.sh`, `scripts-part1.sh`, `scripts-part2.sh`, `finalize.sh`).

## 🚀 Die Dual-Builder-Architektur & Skript-Zuordnung

### 1. Der GL.iNet Quellbasis-Builder (`build-gl-mt5000-glinet.yml`)
- **Zweck:** Universelle Quellcode-Kompilierung auf Basis des offiziellen, nativen GL.iNet-Quellbaums (`mt5000`-Branch) als Kernel- und Treiberfundament.
- **Workflow & Auswahl:** Gesteuert über ein `workflow_dispatch`-Dropdown (`target_env`) für 4 Umgebungen (`immortalwrt_master` [Standard], `immortalwrt_stable`, `openwrt_main`, `openwrt_stable`) für gezielte Einzel-Builds oder die Option `all`, um alle 4 Varianten parallel in einer Matrix zu bauen.
- **Zugeordnete Skripte:**
  * `sh/scripts-part1.sh`: Pre-Feed-Skript, das direkt nach dem Klonen des nativen GL.iNet-Baums ausgeführt wird; setzt Standard-IPs (z. B. `192.168.100.1`) und steuert Feed-Zuweisungen.
  * `sh/scripts-part2.sh`: Post-Feed-Skript zum Klonen von Zusatzpaketen (Themes, Diskman etc.) nach `package/custom`, Bereinigen von Makefile-Konflikten sowie Konfigurieren von Netzwerk-Layout und Branding.
  * `sh/finalize.sh`: Post-Build-Skript zum Umbenennen, Organisieren und Verpacken der finalen Firmware-Artefakte mit Zeitstempel.

### 2. Der Vanilla Source & Patch Builder (`Imagebuilder gl-mt5000.yml`)
- **Zweck:** Holt direkt den Upstream-Quellcode von Vanilla OpenWrt oder ImmortalWrt ab und wendet spezifische Kernel-Patches, Device Tree Sources (DTS) und Treiberanpassungen während eines vollständigen Kompiliervorgangs über dedizierte Hilfsskripte und Patch-Ordner an.
- **Workflow & Auswahl:** Ebenfalls gesteuert über ein `workflow_dispatch`-Dropdown (`target_env`), wobei `immortalwrt_master` als Standardauswahl vorbelegt ist. Ermöglicht wahlweise den gezielten Bau einer einzelnen Umgebung (`immortalwrt_master`, `immortalwrt_stable`, `openwrt_main`, `openwrt_stable`) oder über die Auswahl `all` den parallelen Matrix-Build aller 4 Umgebungen gleichzeitig.
- **Zugeordnete Skripte & Ordner:**
  * `sh/clone.sh`: Hilfsskript zum Klonen spezifischer Upstream-Repositories und Einrichten isolierter Zielverzeichnisse.
  * `sh/prepare.sh`: Bereitet den Quellbaum vor, injiziert benutzerdefinierte Device Tree Sources (DTS) aus `board/` und wendet die Kernel-Patches an.
  * `sh/finalize.sh`: Benennt die fertigen Images um und bereitet die Artefakte für den GitHub-Release vor.

# 🇷🇺 Русская версия (Russian Version)

Этот репозиторий содержит две отличные архитектуры сборки, разработанные специально для роутера **GL.iNet GL-MT5000 (Brume 3)**: универсальный GL.iNet builder на основе исходного кода и builder OpenWrt/ImmortalWrt с применением патчей к исходному коду.

> ⚠️ **Важное примечание о снимках и управлении пакетами:** 
> Все прошивки, генерируемые этим репозиторием, являются **снимками разработки**. Из-за непрерывного характера снапшот-сборок и строгих завязок на версию ядра в OpenWrt/ImmortalWrt **программное обеспечение, зависящее от ядра (например, модули ядра или драйверы), не может быть установлено после установки** с помощью менеджеров пакетов (таких как `apk` или `opkg`). Любые необходимые модули или функции, связанные с ядром, **должны быть явно выбраны и интегрированы непосредственно в процесс сборки посредством конфигурационного списка (`.config`) заранее**.

## 🚀 Дуальная архитектура сборки и распределение скриптов

### 1. GL.iNet builder на основе исходного кода (`build-gl-mt5000-glinet.yml`)
- **Назначение:** Универсальная компиляция исходного кода с использованием официального, родного дерева исходного кода GL.iNet (ветка `mt5000`) в качестве основы для ядра и драйверов.
- **Workflow и выбор:** Управляется через выпадающий список `workflow_dispatch` (`target_env`), поддерживающий 4 окружения (`immortalwrt_master` [по умолчанию], `immortalwrt_stable`, `openwrt_main`, `openwrt_stable`) для целевых одиночных сборок, или `all` для запуска параллельной матричной сборки всех 4 вариантов одновременно.
- **Назначенные скрипты:**
  * `sh/scripts-part1.sh`: Скрипт pre-feed, выполняемый сразу после клонирования родного дерева GL.iNet; устанавливает IP-адреса по умолчанию (например, `192.168.100.1`) и настраивает feeds.
  * `sh/scripts-part2.sh`: Скрипт настройки post-feed, который клонирует сторонние пакеты (темы, diskman и т.д.) в `package/custom`, разрешает конфликты Makefile и обрабатывает сетевую компоновку и брендинг.
  * `sh/finalize.sh`: Пост-билд скрипт для организации, переименования и упаковки финальных артефактов прошивки с отметками времени.

### 2. Vanilla builder исходного кода и патчей (`Imagebuilder gl-mt5000.yml`)
- **Назначение:** Получает исходный код Vanilla OpenWrt или ImmortalWrt непосредственно из upstream и применяет пользовательские патчи ядра, источники устройственных деревьев (DTS) и модификации драйверов во время полного процесса компиляции с использованием специализированных вспомогательных скриптов и каталогов патчей.
- **Workflow и выбор:** Управляется через выпадающий список `workflow_dispatch` (`target_env`) с `immortalwrt_master` в качестве значения по умолчанию. Позволяет собрать одно конкретное окружение (`immortalwrt_master`, `immortalwrt_stable`, `openwrt_main`, `openwrt_stable`) или выбрать `all` для параллельной матричной сборки всех 4 окружений с использованием динамической JSON-матрицы.
- **Назначенные скрипты и папки:**
  * `sh/clone.sh`: Вспомогательный скрипт для клонирования конкретных upstream-репозиториев и настройки изолированных целевых каталогов.
  * `sh/prepare.sh`: Подготавливает дерево исходного кода, инжектирует пользовательские источники устройственных деревьев (DTS) из `board/` и применяет необходимые патчи ядра.
  * `sh/finalize.sh`: Переименовывает, завершает и упаковывает скомпилированные образы прошивки для выпуска.

## 📁 Структура репозитория и каталогов

- `.github/workflows/`: Содержит все автоматизированные конвейеры CI/CD для сборки и выпуска (включая `build-gl-mt5000-glinet.yml` и `Imagebuilder gl-mt5000.yml`).
- `board/`: Содержит аппаратно-специфичные определения плат, цели Makefile (`filogic.mk`), конфигурации устройств и активы устройственных деревьев.
- `config/`: Профили конфигурации, специфичные для прошивки (например, `mt5000.config` и `immortalwrt.config`).
- `default-settings`: Пакет пользовательских настроек по умолчанию для личных конфигураций (в настоящее время не используется).
- `files/`: Наложение rootfs, которое копируется непосредственно в целевую файловую систему во время сборки.
- `patches/`: Общие патчи ядра и исходного кода, применяемые во время сборок vanilla.
- `patches-25.12/`: Наборы патчей, специфичных для версии, предназначенные для стабильных веток версии 25.12.
- `patche618/`: Специфичные патчи и настройки драйверов для ядра 6.18.
- `sh/`: Содержит все модульные вспомогательные и настраивающие скрипты (`clone.sh`, `prepare.sh`, `scripts-part1.sh`, `scripts-part2.sh`, `finalize.sh`).
